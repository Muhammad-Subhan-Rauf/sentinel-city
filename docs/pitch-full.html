Problem & use case · demo step 1

In a disaster, the bottleneck is
human coordination.

When a fire or flood hits a dense block, the firefighters aren't the slow part — the decision loop is. Dozens of panicked, contradictory 911 reports have to be fused into one incident, sized, cordoned, matched to the nearest units, and turned into a public warning — today, through overloaded humans on radios, one incident at a time.

Sentinel-City puts AI on that loop, with humans supervising — and the citizen standing inside the hazard gets the same brain on their phone.

1000sof simultaneous reports in a mass event — far past what a dispatch room can triage by hand.
N×duplicate, conflicting calls about the same fire must be de-duplicated, not double-dispatched.
0situational awareness for the citizen deciding which way to walk out of the zone.

Use case: dense-city multi-incident response · operator-supervised · AI on the loop.

Agentic behavior & reasoning · 25% of score

The model proposes. Deterministic code disposes.

◉

Visual triage Gemini · tool

Gemini reads the 911 transcript and chooses — via a real function-call — whether to pull a CCTV frame. Severe/ambiguous → pull; clear-minor → text-only. Genuine conditional tool use, rationale logged.

pipeline/agent.py · bind_tools([GetCCTVFeed])

◎

Dispatch planner Gemini · structured

Given live per-station capacity + the incident profile, Gemini sets per-station truck counts by doctrine, not a fixed table — so casualties or many reports change the response.

pipeline/dispatch_agent.py · with_structured_output

⊙

911 authenticity Gemini · vision

Weighs transcript + disaster context + attached photo → genuine / uncertain / likely_prank. Advisory only — it re-prioritizes, never silently drops a call.

pipeline/prank_check.py

…and the deterministic rails the model cannot bypass

cluster.py derives confidence from report density (not the LLM's self-rating) · should_declare gates on ≥2 corroborating reports, confidence ≥ 0.5, 800 m dedup & operator cooldown · dispatch counts are clamped to real capacity, hallucinated stations dropped, total capped at 10 · execute.py commits behind SELECT … FOR UPDATE as the final gate.

This is the honest, repo-verifiable design: three real Gemini decision points over deterministic Python — the agent reasons freely but can't empty the fleet or declare a phantom disaster.

Why this is reasoning, not a script

The agent doesn't fire on one panicked caller and isn't fooled by hyperbole: confidence is computed from how many reports cluster in space & time, and severity escalates by volume — 15 calm callers about one fire still escalate; one hysterical caller can't fabricate a "critical".

Reason → act → observe

It crosses a threshold, acts with real side-effecting tool calls, and produces an observable outcome on three surfaces. That loop — not a single prompt answer — is what makes it an agent rather than a summarizer.

Robustness & edge cases · demo step 6 · 10% of score

Built to survive the messy input.

Noisy / hyperbolic report

"The whole city is doomed!!" is still extracted to a typed schema; severity follows a strict rubric and density-derived confidence — one dramatic caller can't manufacture a "critical".

Duplicate / conflicting reports

Same-type reports within 800 m are de-duplicated; execute.py commits behind a row lock, so two near-simultaneous declares attach to one incident instead of spawning a twin.

Likely-prank 911 photo

A meme/selfie attached to a call → vision check returns likely_prank and de-prioritizes — but never silently drops it. assess_call never raises; on error it returns "uncertain" so the call still reaches dispatch.

Tool / API failure

Triage timeout → text-only NLU. Dispatch-agent error → ([], reason), dispatch nothing, log it. Over-request → clamped to real capacity; hallucinated station → dropped. The pipeline never crashes on a model error.

cluster.py · prank_check.py (never raises) · dispatch_agent.py (capacity clamp + fail-safe) · execute.py (row lock). Lock 3 judge-input variants and rehearse each end-to-end (see notes).
